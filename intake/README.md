# 客户 intake —— 怎么用

`_template.yaml` 是**表本身**:一份带注释的 YAML,客户(或你陪着客户)直接在里面填。
它同时是机器读的格式和给人填的格式 —— **只有一份**,不存在"YAML 和 Word 版对不上"的问题。

## 为什么填好的表不进这个仓库

填好的表里有**客户名、竞品、禁问话题** —— 那是客户机密,而这个仓库是公开的。

```
geo-scanner/intake/_template.yaml          ← 在仓库里(空白模板,无客户数据)
default-workspace/clients/<客户名>.yaml     ← 在仓库外(填好的,绝不提交)
```

## 三步流程

```
1. 客户填 intake            →  clients/<客户名>.yaml
2. 生成 25–30 题题库         →  交客户确认(报告第一节会写"谁确认的")
3. 只有确认后才跑测量        →  冻结题库,复测时不许改题
```

**第 2 步的"客户确认"不能省。** 题库是报告的骨架:骨架错了整份报告就是废话 ——
这已经发生过一次(把行业问成了另一个行业,差点把无效数字写进交付物)。

## 行业细分怎么处理(重要)

**我们不建行业分类表。** 世界上有几万个细分,任何表都不全,而且分类表本身不产生价值。

行业细分是**客户的输入**,不是我们的数据。三层结构里只有前两层是我们的:

| 层 | 内容 | 谁负责 | 数量 |
|---|---|---|---|
| **问法原型** | 品类发现 / 场景需求 / 对比选型 / 事实核验 | 我们(固定) | 4 |
| **问法骨架** | 带槽位:`{品类词}` `{客群}` `{市场}` `{竞品}` `{痛点}` | 我们(基本固定) | ~30 |
| **实例化** | 把客户的词填进槽位 | **客户** | **无限,零额外成本** |

所以行业再多,我们这边的工作量不变。需要客户的词时,用**术语采集**三步(见 `_template.yaml`
的 `industry.term_candidates`):

```
① 客户官网/落地页自动抽取(他们自己的原话)   ← 免费、自动
② 问一次 LLM:这个细分有哪些子品类、用户会怎么问、有哪些行话  ← 单次调用,几毛钱
③ 客户勾选确认                                ← 唯一权威
```

**LLM 只提议,不定稿。** 而**长尾由客户负责** —— 客户比任何列表都懂自己的细分。
我们提供的是**结构**(该问哪几类问题)和**纪律**(每题 3 次、只报次数、公开方法),
不是"我们懂他们的行业"。

分类表只在两处值得保留,而且都不是完整表:

- **合规路由**:判断依据是"**有没有监管限制**",不是"属于哪个行业"(按行业猜会漏掉食品广告法、
  教育宣传口径这类)。所以有 `compliance.sensitive`,而不是靠 `sector` 推断。
- **来源先验**:金融→财经媒体/监管公示;餐饮→点评/外卖/加盟目录。这只是来源地图的**提示起点**,
  不是必须命中的表。

## 每个字段都写了「改变什么」

规则是:**没有作用的字段不许存在**。一个字段如果改变不了任何输出,就是在让客户白填,
而摩擦会让表填不完。加字段之前先回答"它改变输出里的哪一部分"。

## 必填与降级

标了 **必填** 的字段缺失时,报告质量**优雅降级**,不报错:

| 缺了什么 | 后果 |
|---|---|
| 无官网 / 域名 | 报告走"纯可见度"那条路,不出技术可读性章节 |
| 无竞品 | 不出对比题与对比章节(报告里写明"本次没有测量竞品") |
| 无曾用名 / 别名 | 实体歧义诊断会漏掉一部分(今天的问题正是从这里漏出来的) |
| 无 markets | 默认单市场、单语言,并在报告里写明 |
| 无 forbidden_topics | **不建议开跑** —— 合规、在诉、未发布产品一旦被问进去,报告就不能发了 |
